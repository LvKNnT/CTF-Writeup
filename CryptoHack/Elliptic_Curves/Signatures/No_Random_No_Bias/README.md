# No Random No Bias Writeup

## Summary

This ECDSA-style challenge uses deterministic nonces derived from the private key and message hash. The nonce construction leaks enough structure for a Hidden Number Problem lattice attack. Recovering the signing key allows the hidden flag point to be decoded.

Flag:

```text
crypto{3mbrac3_r4nd0mn3ss}
```

## Triage

The source signs messages with a nonce derived from:

```text
SHA1(private_key || message_hash)
```

The transcript gives the public key, several signatures, and a hidden flag point. The solver uses the known SHA1-sized nonce bound to build a lattice.

## Solve Path

For each signature:

```text
s_i * k_i - h_i = d * r_i mod n
```

The nonce is bounded by the SHA1 output size, so the unknowns fit a Hidden Number Problem setup. The Sage solver constructs the HNP lattice, reduces it, and extracts the candidate private key `d`.

With `d` recovered, the hidden flag point is decoded by multiplying with `d^-1`, yielding bytes.

## Exploit

Use `solve.sage`. It:

- parses the challenge signatures and public data,
- builds the lattice for the biased nonce relation,
- runs LLL,
- recovers the private key,
- decodes the flag point.

Run it with:

```bash
sage solve.sage
```

## Lessons Learned

- ECDSA nonces must be unpredictable or generated by a proven deterministic scheme.
- Partially bounded nonce information can be enough for an HNP lattice attack.
- Once an ECDSA private key is recovered, any challenge data encrypted or encoded with that key is exposed.
